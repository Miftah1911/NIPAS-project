The Problem

Bangladeshi smallholders face five compounding crises

🚱

Groundwater depletion

Flood irrigation in northern districts wastes massive water volumes. Aquifers are dropping faster than they recharge.

💸

Chemical overuse & input costs

Broadcast fertilization drains farmer income and degrades soil biology. Most doses are wasted on non-target areas.

🌱

Root zone damage from manual testing

Hand-digging soil samples severs delicate root architecture and opens infection pathways.

🍂

Diseases spread undetected

Chlorosis, blight, and bacterial spot destroy tomato, chili, and brinjal crops within days — before visual symptoms are obvious.

👷

Labor-intensive manual monitoring

Walking fields daily to inspect every plant is physically impossible for aging farmers and family-run plots.

Core Purposes

Four missions that drive every design decision

💧

Precision Resource Management

Deliver targeted micro-doses of water and chemicals instead of broadcast irrigation — saving every drop and every taka.

🦾

Non-Invasive Subterranean Monitoring

Retract-and-extend probe samples root-zone soil without cutting into delicate plant architecture.

📷

Autonomous Disease Detection

HSV color analysis on every plant, at every row — before symptoms become visible to the human eye.

📡

Local-First IoT Control

The robot runs its own WebSocket server. Farmers control it from a phone browser — no cloud subscription, no SIM card, no monthly fee.

The main ESP32 owns motion and decision logic. The ESP32-CAM owns vision and disease classification. They communicate over a simple UART protocol — the CAM sends one JSON line per scan. This split keeps each processor focused and lets the robot keep moving even if the CAM stalls.

Autonomy Factors

What makes the robot run on its own

📏

Odometry via Encoders

The robot tracks distance using wheel rotations. Every 20 ticks = one wheel revolution = ~20 cm.

  • Knows exact row position
  • Triggers scan at correct spacing
  • Detects row end without GPS
🚧

Reactive Obstacle Avoidance

HC-SR04 continuously samples the path ahead. Any barrier within 15 cm triggers a state change.

  • Back up + turn sequence
  • Retries path after obstacle clears
  • Escalates to ERROR if stuck
🔄

Row-End Detection

Encoder ticks since row start are compared against the configured row length.

  • Auto turn on reaching end
  • Row counter increments
  • Field finish when total rows reached
🎯

Adaptive Spray Dosing

Spray duration is computed from infection severity — not fixed.

  • Healthy leaf → 0 ms spray
  • Mild infection → 800 ms
  • Severe infection → up to 2500 ms
🔗

UART Handshake with CAM

The CAM responds with a 3-second timeout. If it fails, robot assumes healthy and continues.

  • Never blocks indefinitely
  • Fails safe on CAM crash
  • Retries next plant
📡

MQTT Resilience

State is published continuously. If WiFi drops, robot keeps working — messages queue for reconnect.

  • Offline-first design
  • QoS 1 guarantees delivery
  • Last Will announces disconnect
Decision Walkthrough

What happens every 40 cm of travel

1️⃣

Encoder tick threshold reached

Robot has traveled 40 cm (configurable). Ticks since last scan = 20.

2️⃣

Motors stop, settle delay

400 ms pause lets the chassis stabilize so the camera doesn't blur.

3️⃣

CAM requested over UART

Main ESP32 sends "SCAN\n". CAM sweeps L → C → R with SG90.

4️⃣

CAM returns HSV result

JSON: {infection: 0.22, severity: "moderate"}

5️⃣

Decision + spray + resume

If infection > 5%: relay fires for 800–2500 ms. Then MOVING again.

Honest Assessment

What we haven't solved yet

Being honest about limitations is what separates a real engineering project from a hobby demo.

📐

Approximate 180° turns

Without a gyro or compass, the turn is timed. Small drift accumulates over long rows — self-corrects but not perfect.

📷

HSV is sunlight-sensitive

Cloudy days shift the HSV values. A calibration step or AWB-locked camera would improve robustness.

🌾

No weed vs crop distinction

The camera can't yet tell a chili plant from a weed with similar hue. Would need shape analysis or a trained model.

🔋

Runtime limited by pump

12V pump draws 1–2 A. Two 18650 cells give ~2 hours of continuous work — enough for demo, tight for a full field.

🧪

Single-tank chemical

Current design has one reservoir. Mixing fertilizer and fungicide would need a second pump + tank.

Future Scope · 1

The current design uses off-the-shelf modules wired on a breadboard. The next step is a custom PCB that integrates everything.

Future Scope · 2

Where NIPAS goes next

PHASE 01 · 3 MONTHS

Custom PCB Rev 1

Single-board controller with integrated motor driver, power management, and JST connectors. Eliminates 80% of wiring failures.

PHASE 02 · 6 MONTHS

MPU6050 Gyro + Precision Turns

Add a 6-DOF IMU for closed-loop heading control. 180° turns become exact, not timed. Row drift drops to < 1 cm.

PHASE 03 · 9 MONTHS

On-Device TinyML Disease Model

Replace HSV with a quantized MobileNet or YOLO-Nano model running on ESP32-S3. Detects weeds, distinguishes multiple diseases, works under any lighting.

PHASE 04 · 12 MONTHS

Sunlight-Adaptive Camera

Add ambient light sensor + servo-controlled diffuser. HSV ranges auto-calibrate based on measured illumination.

PHASE 05 · 18 MONTHS

Multi-Robot Swarm

Three or more NIPAS units share a single MQTT broker. Dashboard shows all robots on one field map. Collision avoidance via shared state.

PHASE 06 · 24 MONTHS

Solar + Swappable Battery

Roof-mounted 10W solar panel + hot-swap 18650 pack. Full-day runtime without grid charging. Truly off-grid.

PHASE 07 · 36 MONTHS

Bangla-Language Voice Interface

Offline wake-word + Bangla TTS lets farmers ask "কত আর্দ্রতা?" and hear live soil moisture — no phone needed.
